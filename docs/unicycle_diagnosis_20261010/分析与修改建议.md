# Unicycle 超时原因与修改建议（2026-10-10）

主要原因是 strict T*-only 删除了能够满足 Unicycle 转向约束的其他连接时长。此次只增加独立诊断和证据；正式配置、production 内核和正式可执行文件没有改动。
分析期间原 20261007 目录被移至 20261010；本报告保存在含有同一诊断数据和正式二进制的新位置。历史 manifest 中的路径保留运行时原值。

## 同 seed 对照

Release、float32_production、单核 affinity=[0]、seed=41、10 s 预算、latency、shortcut=false、range=0.30。
配置只改变 time_policy、additional_time_samples 和输出目录，其他参数完全相同。

| 时间策略 | Bugtrap | Wall |
|---|---|---|
| candidate_set / 12 | 首解 0.412148 s | 首解 0.006447 s |
| optimal_only / 0 | 10 s 无首解 | 10 s 无首解 |

上一轮 candidate_set / 0 在 3 s 内同样失败；只保留驻点、min_time、max_time 没有恢复这两个 seed 的可行连接。
这些是本机单 seed 的定位实验，不能当作正式成功率统计或性能提升结论。

这个对照同时说明：当前模型、sphere geometry、正向 branch 和其他搜索参数能完成这两题。
无需先改成双 branch、放宽物理约束或增加人工地图 Guidance。预算过短不是此次主要解释。

## 真正的拒绝原因

原 production CSV 显示大量 df_rejected，但其 SIMD 路径没有把角速度拒绝同步计入 df_omega_rejected。
因此不能看到 df_omega_rejected=0 就判断没有角速度违规。

独立诊断复用原 Release 库、相同 float Bernstein 与时间采样、原 DF/control/collision checker。
前 2000 次迭代中，按首次失败批次、DF→state→control→collision 优先级分类：

| 首次拒绝分类 | Bugtrap | Wall |
|---|---|---|
| omega 超限 | 5095 | 10717 |
| collision | 269 | 929 |
| control bounds | 0 | 14 |
| 零速证书 Uncertain | 21 | 22 |

omega 占这些拒绝分类约 94.6% / 91.7%。这不是完整曲线上所有违规条件的独立计数；同一条边可能同时违反多个条件。
Uncertain 表示未能确认安全，不能等同于已证明速度为零。零速证书不是此处主要拒绝来源。
诊断额外扫描和重试会影响运行时间，其 wall-clock 不参与 latency 比较。
2000 iteration cap 只用于诊断程序，正式 max_iterations/max_nodes 仍为 0。

## 同一局部目标的可复核例子

起点 y_dot=(0.30,0)，目标距离 0.30 m、偏转 30°，自由终端速度：

- T*=0.7238 s，最大 |omega|≈2.8632 rad/s，违反原模型 1.5 rad/s 上限。
- T≈1.0857 s，重新求解 PFF 后，通过原 PFF + DF + SIMD checker。

这里保持相同 y0、dy0、yf；自由终端速度随新 T 重新求解，没有固定旧的自由终端速度。
最先拒绝的 128 条连接中，有限候选重试救回 Bugtrap 13 条、Wall 22 条。重试只作诊断，不写入树。
救回比例不是对所有失败边的保证；未救回也不证明连续时间区间里不存在其他可行时长。

自由终端速度的 cubic 满足：

```
d = yf - y0 - T*v0
a(0) = 3*d/T²
omega = (vx*ay - vy*ax)/(vx² + vy²)
```

当 v0=(0.30,0) 时，omega(0)=3*delta_y/(0.30*T²)。
30°、0.30 m 的 delta_y=0.15，仅起点角速度约束就要求 T>=1 s；T*=0.724 s 必然失败。
最小化 J=T+积分(y_ddot^T R y_ddot) 的无约束时间驻点没有包含这个物理条件。

Wall 另有 min_vel=0.25 m/s。延长 T 可能降低速度并触发最小速度拒绝，所以可行性关于 T 不保证单调。
不能盲目一直倍增时间，或者简单二分就宣称找到了最优可行 T；改变 T 也会改变曲线及碰撞情况。

## 具体修改路线

### 1. 保留 strict T*-only，另建恢复对照

已验证有效的恢复配置：

```yaml
planner:
  stop_at_first_solution: true
  rewire_before_first_solution: false
pff:
  time_policy: candidate_set
  additional_time_samples: 12
postprocess:
  shortcut: false
```

用单独 preset 和结果目录，保留 optimal_only / 0 的严格消融标签。
不要把恢复多时间候选的结果写成 strict T*-only 结果；本次尚未改动正式默认 YAML。

### 2. 新增有限 T* 邻域的可行时间模式

建议新策略名称 optimal_then_feasible，保留已有 optimal_only 行为不变。

1. pff/r2_float_kernel.h：先找 T*，再生成有限的邻域候选，限制在 [min_time,max_time]、去重、按真实 J 排序。
2. 候选同时考虑略小和略大于 T*。初步可对照倍率 {0.8,1.1,1.25,1.5,2.0}，固定统一预算；这些参数尚未验证成功率。
3. 每个新 T 都重新调用 fixedTime，保持原 y/dy 边界契约和 free/fixed terminal semantics；不只是改时间戳或缩放导数。
4. 先验证最低代价的 T*，失败后允许原 validator 验证其他候选。所有候选继续执行零速、速度、omega、state/control 和 collision 检查。
5. production_runner.cpp 解析模式、倍率、预算，拒绝非法参数；tools/run_six.py 和 manifest 记录策略及参数。
6. parent、goal、rewire、shortcut 使用相同策略和 J；按 g+J 选有效候选，不能把“第一个任意可行时长”替代统一代价排序。
7. 现有树循环已经遍历 PFF 候选集合，可复用；goal cache 要保存当前策略的全部候选，不应在仅测 T* 后把有其他候选的整条连接封死。

若少量邻域仍失败，是否启用较宽的有限集合必须是明确选项与独立消融，不保证每条物理可行边都能找到。
可以先返回排序的少量候选集合复用现有 RRT*，再考虑懒生成；不必为本次问题重写 Near 或树管理。

### 3. 修复诊断计数

修改 df/simd_inverse.h、simd/physical_batch.h、simd/physical_avx2.cpp 和 production/float_validator.h：

- 保持现有 valid_mask 条件，增加 numeric / speed-zero / speed-max / omega failure masks。
- 按明确的逐边首次拒绝规则更新 df_omega_rejected 等字段，避免误读 CSV。
- Wall 的正向最小速度拒绝独立统计。
- 区分确定零速和 speed_certificate_uncertain。
- 记录 T* 尝试、fallback 尝试/成功，以及实际采用时长。

这些改动只增加可解释性，不放松物理限制。

### 4. 验证

同一机器人在两张地图使用同一策略及参数。先比较 strict、candidate_set / 12、有限 T* 邻域，再做 20 seeds、120 s。
测试自由/固定端点、T* 的起点 omega 必然超限、换时长可救回、延长时间反而违反最小速度，以及 AVX/scalar 一致性。
本阶段不改 branch、Near、R、robot model、sphere decomposition 或 collision resolution。
