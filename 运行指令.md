# Ubuntu 完整指令：latency / anytime / T*-only（2026-10-09）

本轮默认：latency、optimal_only、additional_time_samples=0、shortcut=false。
anytime 使用独立 preset，首解前 rewiring=true。原 noguidance 副本不参与修改。
以下路径对应你给出的 Ubuntu 目录；DynoBench 路径只需包含 envs、models、dynobench/utils/viewer，不要求 Windows 的双重嵌套。

你的 traceback 显示 Python 3.10；下面的绘图依赖版本按该环境配置，避免系统旧 SciPy 与用户 NumPy 混用。

## 2. 六环境同 seed 对照，并生成官方环境图

先对照 candidate_set / 0 与 optimal_only / 0，两组均关闭 shortcut，不在首解前 rewiring。
这段默认每问题 1 seed、60 s 失败保护、seed 20；属于排查实验，不是正式 20 seeds 统计。

```bash
(
set -e
project_dir="/home/cxt/MYFILE/newfile/RRTstar/RRTstarDFPFF_paper_r2_float32_strict_20261007"
dynobench_dir="/home/cxt/MYFILE/newfile/dynobench-main"
build_dir="$project_dir/build"
cd "$project_dir"
unset PYTHONPATH PYTHONHOME
source .venv_protocol_viewer/bin/activate
export MPLBACKEND=Agg
cpu="$(python -c 'import os; print(min(os.sched_getaffinity(0)))')"
experiment_root="$project_dir/results/time_policy_compare_$(date +%Y%m%d_%H%M%S_%N)"
mkdir -p "$experiment_root"

run_checked() {
  local task_status=0
  "$@" || task_status=$?
  if [ "$task_status" -ne 0 ] && [ "$task_status" -ne 2 ]; then
    return "$task_status"
  fi
}

run_checked python tools/run_six.py \
  --dynobench-source "$dynobench_dir" --build-dir "$build_dir" \
  --protocol latency --runs 1 --timeout 60 --seed 20 --cpu "$cpu" \
  --time-policy candidate_set --additional-time-samples 0 --shortcut false \
  --output "$experiment_root/latency_candidate_zero"
python tools/verify_results.py "$experiment_root/latency_candidate_zero"

run_checked python tools/run_six.py \
  --dynobench-source "$dynobench_dir" --build-dir "$build_dir" \
  --protocol latency --runs 1 --timeout 60 --seed 20 --cpu "$cpu" \
  --time-policy optimal_only --additional-time-samples 0 --shortcut false \
  --output "$experiment_root/latency_optimal_only"
python tools/verify_results.py "$experiment_root/latency_optimal_only"

for name in latency_candidate_zero latency_optimal_only; do
  python plot_successful_results_paper.py \
    --experiment "$experiment_root/$name" --dynobench-source "$dynobench_dir" \
    --run 0 --mode dynobench --trajectory raw --skip-failed \
    --output "$experiment_root/$name/figures_raw"
done

cat "$experiment_root/latency_candidate_zero/summary.csv"
cat "$experiment_root/latency_optimal_only/summary.csv"
printf 'Results: %s\n' "$experiment_root"
xdg-open "$experiment_root/latency_optimal_only/figures_raw/index.html" >/dev/null 2>&1 || true
)
```

两组同 CPU、同构建、同 seed、同 timeout。各 case/results.csv 查看 first_solution_time、first_solution_cost、search_time、success、termination_reason。
去掉均匀时间候选后，candidate_set / 0 仍可验证多个驻点和时间上下界；optimal_only 仅验证代价最低的一项，失败不继续试其他时长。
如需旧 12 候选消融，另建结果目录，使用 --time-policy candidate_set --additional-time-samples 12。

## 3. 正式 latency：20 seeds、首解退出、shortcut 关闭

```bash
(

```

seeds 为 41..60；run 0 为 seed 41，run 19 为 seed 60。首解前不 rewiring，首解后立即退出。
120 s 是失败保护，主要比较 t_first、J_first 和成功率。

## 5. 稳定后单独开启 Algorithm 4

另建实验目录，将 latency 命令中的 --shortcut false 换成：

```bash
--shortcut true --shortcut-mode flask --shortcut-time optimal
```

开启后分别保存 trajectory_raw_N.yaml 与 trajectory_shortcut_N.yaml，单独记录 shortcut_time。
包含后处理的时间为 total_time=search_time+shortcut_time；anytime_N.csv 仍只表示原树搜索代价，不包含 shortcut 改善。
绘图分别使用 --trajectory raw 和 --trajectory shortcut，两个 output 目录必须不同。

## 6. 已有成功结果只补绘图

这段不重新规划，可修复你之前因 NumPy/SciPy 混用导致的空 figures。修改 experiment_dir 指向实际结果目录。

```bash
(
set -e
project_dir="/home/cxt/MYFILE/newfile/RRTstar/RRTstarDFPFF_paper_r2_float32_strict_20261007"
dynobench_dir="/home/cxt/MYFILE/newfile/dynobench-main"

cd "$project_dir"

source .venv_protocol_viewer/bin/activate
export MPLBACKEND=Agg
plot_dir="$experiment_dir/figures_fixed_$(date +%Y%m%d_%H%M%S_%N)"
python plot_successful_results_paper.py \
  --experiment "$experiment_dir" --dynobench-source "$dynobench_dir" \
  --run 0 --mode dynobench --trajectory final --skip-failed --output "$plot_dir"
xdg-open "$plot_dir/index.html" >/dev/null 2>&1 || true
)
```

调试显示可用 --mode checker_geometry 或 --mode trajectory_only。正式结果使用 dynobench 原始环境显示。
若某 seed 失败，--skip-failed 跳过该 case；可选其他 --run（对应 seed offset）查看成功轨迹。
没有成功轨迹时不生成伪造轨迹图。图目录已存在时脚本拒绝覆盖，包括上次失败留下的空目录。
run_six 返回 2 表示至少一项失败；summary.csv 保留失败。任何其他错误码或 verify_results 失败都应排查。
主配置 max_nodes/max_iterations=0；hard_safety_node_cap=1000000 是异常保护，触发不能计作正常成功。
本轮本机验证在 Windows；目标 Ubuntu 的正式实验仍需执行上述命令。
